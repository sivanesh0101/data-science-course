# SQL Window Functions

## What is a Window Function?

A window function performs calculations across a set of rows related to the current row, without reducing the number of rows.

Unlike GROUP BY:

* GROUP BY → reduces rows
* Window functions → keep all rows

---

## Why Use Window Functions?

Used when you need:

* Aggregation + row-level detail
* Ranking
* Running totals
* Comparisons between rows
* Analytical reports

---

## Basic Syntax

```sql id="wf001"
function_name(column) OVER (
    PARTITION BY column
    ORDER BY column
)
```

---

## Key Components

### 1. Function

Examples:

```sql id="wf002"
SUM()
RANK()
ROW_NUMBER()
LAG()
```

---

### 2. OVER()

Defines the window (set of rows)

---

### 3. PARTITION BY

Splits data into groups (like GROUP BY but keeps rows)

---

### 4. ORDER BY

Defines order inside each partition

---

## Example Table

```sql id="wf003"
CREATE TABLE employees (
    name VARCHAR(50),
    dept VARCHAR(50),
    salary INT
);

INSERT INTO employees VALUES
('A', 'IT', 5000),
('B', 'IT', 6000),
('C', 'IT', 6000),
('D', 'HR', 4000),
('E', 'HR', 3000);
```

---

## Example 1: Total Without Grouping

```sql id="wf004"
SELECT name, salary,
       SUM(salary) OVER () AS total_salary
FROM employees;
```

---

## Example 2: Department-wise Total

```sql id="wf005"
SELECT name, dept, salary,
       SUM(salary) OVER (PARTITION BY dept) AS dept_total
FROM employees;
```

---

## Example 3: Running Total

```sql id="wf006"
SELECT name, salary,
       SUM(salary) OVER (ORDER BY salary) AS running_total
FROM employees;
```

---

## Example 4: Ranking

```sql id="wf007"
SELECT name, salary,
       RANK() OVER (ORDER BY salary DESC) AS salary_rank
FROM employees;
```

---

## Example 5: Row Number

```sql id="wf008"
SELECT name, salary,
       ROW_NUMBER() OVER (ORDER BY salary DESC) AS row_num
FROM employees;
```

---

## Example 6: Dense Rank

```sql id="wf009"
SELECT name, salary,
       DENSE_RANK() OVER (ORDER BY salary DESC) AS dense_rank
FROM employees;
```

---

## Difference Between Ranking Functions

| Function   | Behavior                          |
| ---------- | --------------------------------- |
| ROW_NUMBER | Unique sequence                   |
| RANK       | Same rank for ties, skips numbers |
| DENSE_RANK | Same rank for ties, no gaps       |

---

## Example 7: Top N per Group

```sql id="wf010"
SELECT *
FROM (
    SELECT name, dept, salary,
           ROW_NUMBER() OVER (PARTITION BY dept ORDER BY salary DESC) AS rn
    FROM employees
) t
WHERE rn <= 2;
```

---

## Example 8: Previous Row Value (LAG)

```sql id="wf011"
SELECT name, salary,
       LAG(salary) OVER (ORDER BY salary) AS prev_salary
FROM employees;
```

---

## Example 9: Next Row Value (LEAD)

```sql id="wf012"
SELECT name, salary,
       LEAD(salary) OVER (ORDER BY salary) AS next_salary
FROM employees;
```

---

## Example 10: Percentage of Total

```sql id="wf013"
SELECT name, salary,
       salary * 100.0 / SUM(salary) OVER () AS percentage
FROM employees;
```

---

## Execution Flow

```sql id="wf014"
FROM → WHERE → GROUP BY → HAVING → WINDOW FUNCTIONS → SELECT → ORDER BY
```

Window functions are applied after grouping but before final ordering.

---

## Important Notes

* Window functions do not reduce rows
* Can be used with aggregate functions
* Cannot be used in WHERE clause directly
* Can be used in SELECT and ORDER BY

---

## Default Window Behavior

```sql id="wf015"
ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
```

Meaning:

* From first row to current row

---

## Real Use Cases

* Ranking employees by salary
* Running totals (finance, banking)
* Top N per category (e-commerce)
* Analytical dashboards
* Trend analysis
* Duplicate detection

---

## Best Practices

* Use PARTITION BY for grouped analysis
* Use ORDER BY for sequence-based calculations
* Avoid overusing window functions in large datasets without indexing
* Use meaningful aliases

---

## Limitations

* Cannot use directly in WHERE
* Can impact performance on large datasets
* Requires MySQL 8.0+

---

## Summary

* Window functions perform calculations across rows
* OVER() defines how the calculation is applied
* PARTITION BY groups data without collapsing
* ORDER BY defines calculation order
* Used heavily in analytics and reporting
